# 盒马时钟

本项目分叉自 [tpunix](https://github.com/tpunix) 的原版 [HMCLOCK](https://github.com/tpunix/HMCLOCK) 项目。

---

![设备展示](./images/device.png)

## 项目简介

本项目利用超市淘汰下来的 **盒马价签** 硬件，实现一个功能简单但实用的电子时钟，具有如下功能：

* ✅ 模拟时钟表盘 + 日历卡片显示（星期、日期、月份、年份）
* ✅ 显示电池电量
* ✅ 蓝牙对时
* ✅ 时间校准
* ✅ 蓝牙 OTA 更新

## 更新日志

### 0xA50f0010

* **修复了网页端对负数时间校准偏移的编码错误。** 校准写入代码用小数除法（`diff/256`）计算有符号 16 位偏移的高字节，而 JS 的小数除法向零截断——结果走快 N 秒的设备收到的校正是方向错误的"反向"值（例如 -10 秒变成 +246 秒），漂移反而更严重。现改用正确的补码按位运算编码；
* 移除了无用处的 BLE `0x90` 12/24 小时制切换命令及其网页按钮：固件只是翻转一个从未被任何代码读取的标志位（时钟是模拟表盘），该命令实际不起任何作用；
* 网页端（中英文）：此前只存在于 GitHub Pages 发布副本上的蓝牙可用性检查与错误提示横幅，现已合入源码版本——确认存在蓝牙适配器之前连接按钮保持禁用，连接失败时给出可操作的具体提示（无适配器/浏览器不支持/未选择设备/非安全上下文/连接丢失）；
* 网页端健壮性：校准过程中设备断开时，校准按钮不再永久卡在禁用状态（try/finally）；对时前的整秒等待不再空转阻塞 UI 线程；设备时间推算逻辑统一到单一函数（长时间连接期间跨天显示现在正确）；移除了死代码（未使用的 FF03 特征值读取、连接时多余的系统时间写入）；
* 固件清理：刷屏提交序列（4 处重复）与帧缓冲清屏（3 处重复）去重为 `epd_commit()`/`fb_clear()` 辅助函数；移除了 SDK 模板遗留的、从未使用的保持内存全局变量；
* 仓库维护：`docs/index.html`（发布页面）现在由 GitHub Actions 工作流（`.github/workflows/sync-docs.yml`）从 `WebApp/WebApp_EN/index.html` 自动生成——只需修改 WebApp_EN 副本，发布站点会自动同步。

### 0xA50f000f

* **修复了部分设备上固件断电后不保持的问题。** 这类设备的原装 product header 把两个固件槽位指向了相互重叠的地址（`0x2000`/`0x4000`），且启动链无条件从槽位 0 启动——因此自烧写和 OTA 写入"非活动槽位"的更新会被忽略，每次复位都会退回旧固件。现在自烧写会把新固件安装到主槽位（product header 中的槽位 0），并使用比现有槽位都高的、防回绕的镜像编号，无论启动器按哪种策略选择槽位都能启动新固件。完整分析见 `Programming.md`；
* 镜像编号现在防回绕：此前编号直接加一没有检查，更新次数足够多后编号越过 `0x7F` 变成 `0x80`（有符号字符即 -128），导致新镜像的优先级反而排在所有镜像之下；
* 新增可读的蓝牙诊断特征值 **FF04**（32 字节），用于查看启动/OTP 标记、启动头、运行版本，以及上次启动时 Flash 更新的执行情况（安装还是跳过、哪个字段不匹配）。详见 `Programming.md`；
* 新增 `Programming.md`：说明固件保持机制、如何永久烧写（调试器 RAM 加载或 OTA）、Flash 布局与 FF04 诊断参考；
* 配对页面视觉优化：按真实字体度量将各行重新排布为关于二维码中心对称（版本行不再贴住屏幕底边），版本号改为大写（`vA50F000E`），参差不齐的文字虚线分隔符换成绘制在光学中心上的清晰实线，版本号旁新增电池电量图标；
* 时钟表盘优化：表盘不再贴住卡片边框（留出 2 像素边距），中心轴点从笨重的 5×5 缩小为 3×3，不再盖过 1 像素细针；
* 每日午夜残影清除：午夜时面板以完整刷新驱动为纯黑（下一分钟再以强制完整刷新恢复表盘），清除快速/局部刷新累积的电子纸残影——包括原版价签固件留下的红色高亮残影；
* 在 DA14585 配置中重新启用了串口日志（`CFG_PRINTF`）以便调试；注意只要打印日志就会阻止进入 extended sleep，对功耗敏感的构建请关闭。

## 编译与烧写

请先下载 DA14585 的 [SDK](https://www.renesas.com/en/document/swo/sdk60221401-da1453x-da145856 "SDK") 包，目前使用 **6.0.22.1401** 版本。

1. 将本项目放置在：

   ```
   SDK_PATH/projects/target_apps/ble_examples
   ```

2. 使用Keil打开项目进行编译。

3. 编译完成后：

   * **调试模式运行一次**，固件会自动写入 Flash（持久化机制与首次启动的预期行为见 [`Programming.md`](Programming.md)）；
   * 或者使用 **SmartSnippets Toolbox** 将固件下载到 RAM 运行一次也可；
   * 如果使用的是 CMSIS-DAP/ST-Link 调试器而非 J-Link，也可以用 **OpenOCD** 烧写（见下文）。

### 使用 OpenOCD 烧写

DA14585/586 没有内部 Flash —— 固件通常运行在 RAM 中，由调试器直接加载，或由 ROM 启动引导程序从外部 SPI Flash/OTP 拷贝而来。`Keil_5\openocd_da14585.cfg` 通过 SWD 使用 CMSIS-DAP 兼容调试器实现这种“加载到 RAM 并运行”的方式（已在本项目 Keil 的 `CMSIS_AGDI` 调试驱动所配置的同一个调试器上测试通过）。

安装 OpenOCD（例如 `winget install xpack-dev-tools.openocd-xpack`），然后在 `Keil_5` 目录下执行：

```
openocd -f openocd_da14585.cfg -c "ram_load_run out_DA14585/Objects/ble_app_peripheral_585.axf" -c shutdown
```

该命令会暂停内核、将 `.axf` 写入 `0x07fc0000` 处的 RAM、根据中断向量表设置 `SP`/`PC`，然后恢复运行——效果等同于 Keil 的 RAM 调试流程。和该流程一样，固件自身的首次启动逻辑会把自己写入外部 SPI Flash，因此无需额外的烧写步骤即可在断电后保持。

注意事项：

* OpenOCD 没有针对该芯片外部 SPI Flash/OTP 的 flash 驱动，因此 `program`/`flash write_image` 在这里不可用——只有“加载到 RAM”这条路径可行。
* 请使用普通的 `reset halt`，不要加硬件复位加延时：仅内核复位（`SYSRESETREQ`）**不会**重新触发 ROM 的 Flash 到 RAM 拷贝过程（该过程只在上电复位时发生），所以并不存在需要等待的竞争条件。在暂停前加入延时反而可能在内核执行中途捕获，从而触发 HardFault。

## 蓝牙对时

项目内置页面提供 **Web Bluetooth** 功能，可用于手动对时：

* 固件每隔 **整十分钟** 广播一次，持续 **15秒**；
* 广播状态下，屏幕显示蓝牙图标与设备名后缀；
* 打开页面点击 “连接”，选中设备后，按 “同步时间” 即可完成同步。

## 时间校准

根据观察，默认状态下，时钟大概每天会快两秒左右。通过微调定时器的间隔，可以让时钟更精确。
在时间同步后，间隔两到三周，做两次校准，基本上就可以让时钟精准运行了。

* 设备链接后，按"时间校准"按钮，然后等待一分钟左右即可。
* 校准后请立即做一次时间同步。

### Flash存储信息

#### 固件槽位与启动头

启动链（ROM 或价签的 OTP 启动器）会读取 **`0x38000` 处的 product header**（`70 52 ...`），其中包含两个固件镜像槽位的起始地址。每个槽位以 64 字节的 Dialog SUOTA 镜像头开始（`70 51 AA` + 镜像编号、代码大小、CRC32、偏移 28 处的版本号）。

* 槽位地址**并不固定**——应从 product header 中读取。多数设备使用 `0x4000`/`0x1F000`；也有设备使用 `0x2000`/`0x4000` 且两个槽位相互重叠，这类设备的启动链会无条件从槽位 0 启动；
* 自烧写（`src/epd/spi_flash.c` 中的 `selflash()`）会把新构建安装到主槽位，并使用防回绕的镜像编号；详见 [`Programming.md`](Programming.md)；
* `0x00000` 处可能还存在一个旧式单镜像启动头（`70 50 ...`）；在测试过的设备上启动链并不使用它。

#### 屏幕引脚配置（地址 `0x39000`）

示例：

```
09 01 FF FF FF FF FF FF 21 22 10  01  20  07  11  23
                        CS ?? RST CLK SDI DC BUSY PWR
```

* 第一个字节 `09`：屏幕类型
* 第二个字节 `01`：引脚配置启用标志（非 `01` 表示无效）

#### 屏幕分辨率等信息（地址 `0x3a000`）

示例：

```
00 25 00 00 92 fa a8 fe 00 01 80 00 28 01 04 00
                          0080  0128          128x296  BWR
```

## 其他说明

* 原版价签固件存放在 Flash 的 SUOTA 区域；
* 大多数价签使用 OTP 启动器，但会从 Flash 继续加载固件；
* Flash 中包含屏幕 and 引脚配置，因此新固件无需硬编码这些信息；
* 原生固件无法被蓝牙扫描到，因此难以通过 OTA 更新；
* 价签多数电池电量不足，因此建议拆机替换供电。
