# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`AGENTS.md` is the authoritative rules file (web-app single source of truth, BLE command table, version-bump convention, CLI syntax-check recipe). Read it first; this file only adds the big picture.

## What this is

Firmware (Keil MDK 5, armclang V6, Dialog DA14585, SDK 6.0.22.1401) plus a Web Bluetooth page for a repurposed Hema supermarket e-paper shelf label used as an analog clock + calendar. The project must live at `SDK_PATH/projects/target_apps/ble_examples/HMCLOCK` — include paths in `Keil_5/ble_app_peripheral.uvprojx` are relative to the SDK tree. `DA14585` is the only Keil target (the 531/535/586 targets and configs were removed).

## Build / run

- No test suite or linter. Verification = compile + hardware.
- Syntax-check a single source without Keil GUI: the PowerShell recipe in `AGENTS.md` (needs the three forced `-include` headers, no `-D` defines).
- Full build: `UV4.exe -b Keil_5/ble_app_peripheral.uvprojx -t DA14585 -j0 -o build_log.txt` (close µVision first).
- Web app: no build. Check JS with `node --check` on each extracted `<script>` block.
- Every firmware change bumps `EPD_VERSION` (`src/config/user_config.h`) and adds changelog entries to both `Readme.MD` and `README_cn.md`.

## Architecture

- **No internal flash.** Firmware always runs from RAM at `0x07FC0000`; the boot ROM copies an image from external SPI flash each power-on. Firmware therefore *installs itself* into SPI flash on the first boot after a debugger RAM load (`selflash` in `src/epd/spi_flash.c`), and BLE OTA writes the same flash. Slot addresses come from the product header at `0x38000` and differ per unit (some overlap: `0x2000`/`0x4000`) — never hard-code them or erase a region not derived from the header. Details, flash map and the FF04 diagnostic characteristic: `Programming.md`.
- **App layer** (`src/user_peripheral.c`, `src/user_custs1_impl.c`): a minute-tick clock timer redraws the e-paper, advertising runs in bursts (15 s window, periodic re-advertise) to save power, and low battery stops the periodic wake. BLE writes to the custom service (`0xFF00`/`0xFF01`, defined in `src/custom_profile/`) are dispatched in `user_custs1_impl.c` (commands in `AGENTS.md`; OTA in `ota_handle`).
- **E-paper stack** (`src/epd/`): `epd_hw.c` (bit-banged SPI/GPIO, panel power) → `epd.c` (panel detect, commit/refresh; resolution is detected at boot, 212×104 / 250×122 / 296×128) → `epd_gui.c` (framebuffer drawing primitives, fonts in `font*.h`). All screens (clock, pairing QR, low battery) derive layout from the detected resolution; `epd_commit()` and `fb_clear()` are the shared helpers.
- **Config**: no `-D` flags; `da1458x_config_*.h` and `user_config.h` are pulled in by forced includes. `CFG_PRINTF` (UART2 TX = P0.4, 115200) blocks deep sleep while logging — keep off for power-sensitive builds.
- **Hardware**: same PCB as the sibling `../BLE_HID` project; pinouts in `docs/pinout_0.md` / `Hardware/`, SWD test points in `Programming.md`.

## Web app

`WebApp/WebApp_EN/index.html` is the source of truth; `WebApp/WebApp_CN/webApp.html` gets the same logic with translated strings; `docs/index.html` is generated by `.github/workflows/sync-docs.yml` — never edit it. The pairing screen's QR code points at the published copy (`https://terenceang.github.io/HMCLOCK-EN/`).

## Gotchas

- Don't reorder definitions in `user_custs1_impl.c` (`epd_commit()` depends on `epd_wait_timer`/`epd_wait_hnd` being defined above the helpers).
- Command `0x90` was removed on purpose; don't reintroduce it.
- Untracked large files in `docs/` (MDK installer, SDK zip, SmartBond programmer) are local tooling, not to be committed.
